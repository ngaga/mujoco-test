# SO-101 articulated arm on our existing mobile base

This experimental variant mounts the **same six-joint SO-ARM100/101 mechanical MJCF** used by our successful fixed-arm SmolVLA experiment onto the EarlyBots three-degree-of-freedom mobile navigator. It imports actual collision meshes, motors, two-jaw geometry, and TCP from the pinned upstream Apache-2.0 sim2cell package.

The original mobile_demo.run toy XYZ slide arm is NOT used by this variant. It has 9 commands: base x, base y, base yaw, then Rotation, Pitch, Elbow, Wrist_Pitch, Wrist_Roll, Jaw. The original base's physical XY/yaw navigation and two-stage route around the blue bin are retained.

**Honesty boundaries:** This is a physically articulated arm but still uses the simplified holonomic base with decorative wheels. Real omniwheel physics is future work. The arm policy is a scripted oracle with real DLS inverse kinematics, NOT pretrained VLA. The existing pretrained fixed-arm six-dimensional checkpoint cannot by itself navigate a nine-dimensional mobile robot. Cubes are reduced to 24 mm, matching the prior VLA workcell, so the original 48 mm benchmark cannot be compared directly. The real gripper can slip and drop, and the JSON report records those failures. The first single-cube strict physical rollout completed 1/1 at 22.7 s simulated (no retry). This is one deterministic sample, NOT a robustness claim. The arm mount at x=0.14 m and z=0.20 m is a kinematic research placement: it is near the upper outside edge of the proxy chassis and must be mechanically reviewed for a real build. The prior z=0.27 m mount could not reach the floor-level grasp.

## Start

Install from the repository root:

    python -m pip install -r requirements.txt -r mobile_demo/so101_requirements.txt

Verify the real imported model and cameras:

    python -m mobile_demo.so101 --check-model

Run one cube with physical contact, retries and JSON report:

    python -m mobile_demo.so101 --cubes 1 --max-steps 1000 --max-retries 2 --output mobile_runs/mobile_so101.json

Show the simulation in MuJoCo Studio WebViewer on macOS:

    mjpython -m mobile_demo.so101 --cubes 1 --viewer

The strict physical-delivery acceptance check is active in CI. It verifies a settled cube in the bin after real jaw release:

    python -m mobile_demo.so101 --require-success

## Next steps

1. Verify the arm TCP can reach pickup/lift poses given the real SO-101 kinematics and 0.20 m mount height, then calibrate IK if necessary.
2. Measure success across matched randomized real physics trials, not just compile tests.
3. Replace the base servo proxy with the full actual LeKiwi omniwheel model from https://github.com/Ekumen-OS/lekiwi and translate the same navigation waypoints into a wheel controller.
4. Keep navigation and safety supervisory logic separate from pretrained visual policy inference and explicitly adapt camera/action distribution before claiming mobile VLA control.
